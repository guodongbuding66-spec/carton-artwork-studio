# External PDF/X Validator Bridge

> v2.0 trust policy: see `docs/PRODUCTION_PROMOTION_POLICY.md`.

v1.9 adds a strict HTTP bridge for an independent PDF/X validator.

This is an adapter contract, not a bundled validator and not a claim that any specific third-party product is already connected.

## Configuration

Worker variable:

```text
PDFX_VALIDATOR_URL=https://validator.example.com/api/validate
```

Required Worker secret for v2 staging/final acceptance:

```text
PDFX_VALIDATOR_TOKEN
```

The URL must use HTTPS. v2.0 also requires the bearer secret to be present before the bridge is considered configured.

Do not commit the token into `wrangler.jsonc`, source code, GitHub variables, or D1.

For staging, the URL can be supplied through:

```text
CLOUDFLARE_PDFX_VALIDATOR_URL
```

The token should be installed as a Cloudflare Worker secret.

## Request contract

Carton Artwork Studio sends:

```http
POST <PDFX_VALIDATOR_URL>
Content-Type: application/pdf
Authorization: Bearer <token>          # only if configured
X-CAS-PDFX-Profile: PDF/X-4
X-CAS-Artifact-SHA256: <64-hex-sha256>
X-CAS-Promotion-Policy-Version: 2.0.0
X-CAS-Ruleset-Id: CAS-PDFX4-PRODUCTION-1
X-CAS-Ruleset-Version: 1.0.0
X-CAS-Ruleset-SHA256: f658882bd2d367839ea2fb3b3bce027320de4a70d480169feb3ba860588a6d80

<PDF bytes>
```

The candidate PDF is generated by the Worker from:

- the current D1 Artwork canonical snapshot;
- an Approved TrueType FONT asset;
- an Approved CMYK ICC_PROFILE asset;
- exact R2 bytes re-verified by SHA-256;
- an explicit Output Condition Identifier.

## Required validator response

The bridge accepts JSON only.

Example:

```json
{
  "status": "PASS",
  "profile": "PDF/X-4",
  "artifactSha256": "64-character SHA-256",
  "validator": "callas pdfToolbox CLI",
  "version": "17.0.683",
  "rulesetId": "CAS-PDFX4-PRODUCTION-1",
  "rulesetVersion": "1.0.0",
  "rulesetSha256": "f658882bd2d367839ea2fb3b3bce027320de4a70d480169feb3ba860588a6d80",
  "checks": [
    {"name": "PDF/X profile", "ok": true}
  ],
  "report": {
    "providerSpecific": "data"
  }
}
```

Mandatory integrity rules:

- `status` must be `PASS` or `FAIL`;
- response profile must match the requested profile;
- response must include the exact submitted artifact SHA-256;
- SHA-256 must be 64 hex characters;
- validator name and version are required;
- a PASS result must match the v2.0 trusted primary validator identity/version;
- a PASS result must match the pinned ruleset ID/version/SHA-256;
- a response cannot say `PASS` while returning `checks[].ok=false`.

HTTP errors, invalid JSON, SHA mismatch, timeout, or invalid response schema are stored as `ERROR`, not `FAIL`.

## Persistence

Every external validation attempt is written to D1:

`pdfx_validation_runs`

Stored evidence includes:

- Artwork ID;
- immutable Revision;
- PDF/X profile;
- candidate PDF SHA-256;
- validator name/version;
- PASS / FAIL / ERROR;
- checks/report;
- creating identity;
- timestamp.

The same event is also written to Audit Log.

## UI

Quality > Assets now contains two separate actions:

- **Render PDF/X-4 Candidate** — internal structural engineering check;
- **Run External Validator** — sends those deterministic candidate bytes to the configured external validator.

Recent external validation evidence is shown below the candidate controls.

## Production gate

System Readiness adds:

```text
External PDF/X validator configured
```

as a Production gate.

This still does not by itself enable PDF/X-4 production.

The renderer capability remains:

```text
pdfxCandidateProfiles = ["PDF/X-4"]
pdfxProfiles = []
```

v2.0 defines the exact promotion criteria in `docs/PRODUCTION_PROMOTION_POLICY.md`. `pdfxProfiles` remains empty until the complete regression + secondary-validator + real printer/RIP evidence package has been approved.

## Trust model

The bridge validates transport and response integrity, but it cannot determine whether an arbitrary configured endpoint is a competent PDF/X conformance validator.

Production deployment therefore must treat `PDFX_VALIDATOR_URL` as privileged configuration and restrict who can change it.
